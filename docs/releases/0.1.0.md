# S-Eidos 0.1.0 — release notes

**The first release. It reviews front-end code that already exists, and it shows its work.**

## Why this exists

A coding agent will happily tell you that the component it just wrote is modern. It usually means the
syntax is current. It rarely means the code is accessible, that the effect is doing what a render
could do, that the image reserves its space, or that the framework's own idiom was used instead of a
workaround the model saw a lot of in training data.

There is no shortage of guidance telling you what the current platform offers. What is missing is a
tool that looks at the code you already have and says, per site, *this is why this may be wrong, here
is the source, here is when I read it, here is when you should read it again, and here is when you
should ignore me.*

That is S-Eidos. The name is the Greek **εἶδος** — *form, shape, kind*, the root of "eidetic" and "idea". A pattern is
a form; recognising it is what this tool does, and the citation is how it earns the right to say so. **Age is not the
defect, and a shape alone is not a verdict.**

## What you can do with it

- **In DeepSeek Harness.** A `S-Eidos` row in the left sidebar opens the evidence workbench. Ask the
  agent to run `s_eidos_audit` against a directory and then tell you which findings it would
  actually act on.
- **In any terminal.** `node bin/s-eidos.mjs audit src/` for a readable report, `--format json` for
  the machine value, `--fail-on high` for a gate.
- **In another agent environment.** The CLI and the skill's markdown work anywhere a shell command
  does.

## The design decisions a reader should know

**Nothing is flagged for being old.** A rule fires only when a cited source, the project's declared
support target, and a detectable code shape agree. When your declared target cannot run the modern
alternative, the finding is demoted and says why. `insecure` and `inaccessible` are exempt: a target
that cannot run the fix is not a reason to keep the defect.

**`deprecated` is reserved.** The classifier has seven values. Only a source that says "deprecated" or
"removed" earns that word; everything else is `obsolete`, `legacy`, `situational`, `unsupported`,
`insecure` or `inaccessible`. The catalog validator refuses a `deprecated` rule that does not name the
source that calls it that.

**False positives are printed, not implied.** Every rule carries at least one "do not flag when"
condition, and every report prints it beside the finding. A tool whose findings you must re-derive by
hand is a tool you stop reading.

**Evidence expires.** Every citation carries `retrieved` and `review by`. A rule past its review date
is reported as stale rather than presented as current.

**It cannot edit your code.** This release has no apply path at all. The refusal contract that a
future codemod must satisfy is written down and tested — including the canonical refusal,
`innerHTML → textContent`, which silently deletes rendered content and is therefore never `safe`.

**A dismissal is a decision.** `s-eidos decisions add` records a reason and a review date. The
finding stays in the report, marked and counted. Expired decisions are reported, so a suppression
cannot quietly become permanent.

## What it will not do

- Certify anything. `standards` entries are references, not conformance claims.
- Measure LCP, INP or CLS. It finds *causes*, not field metrics.
- Guess at data flow. Rules needing taint tracking are catalogued as deferred, not shipped with
  approximations.
- Phone home. There is no network code in the engine, the tool, or the panel.

## Deliberately small first release

Seven rules ship with detectors, fixtures and end-to-end tests. Thirty more reviewed rules are
catalogued with evidence in `research/legacy-pattern-catalog.md`; each needs a detector and a
false-positive fixture before it may fire. Shipping a wide, noisy rule table would have been easy and
would have contradicted the reason this project exists.

## Upgrading

Nothing to upgrade from. Install the package directory and restart the host.
